A. Cognee compact contract

Highest-confidence behavior fix in the tree. Default auto used to steal the chat checkpoint whenever Blackhole was off and replace it with recall text. After, Cognee stores memory and injects untrusted context for one turn. It does not write the compact summary unless the user sets own.

Before · shouldOwnCompactionSummary
export function shouldOwnCompactionSummary(
  mode: CompactionSummaryMode,
  blackholeActive: boolean = isBlackholeCompactionActive(),
): boolean {
  if (mode === "own") return true;
  if (mode === "defer") return false;
  // auto
  return !blackholeActive;
}
After
export function shouldOwnCompactionSummary(
  mode: CompactionSummaryMode,
  _blackholeActive: boolean = isBlackholeCompactionActive(),
): boolean {
  // auto always defers so a default install cannot
  // replace Pi/Blackhole's checkpoint with a recall dump.
  return mode === "own";
}

Why: a default install was rewriting Pi's compact artifact. The after state matches "Cognee is derived memory, not a second session store."

B. Blackhole minimal tail

Config claimed tailBehavior but before-compact always summarized messagesToSummarize + turnPrefixMessages and kept Pi's firstKeptEntryId. Minimal did nothing. After, resolveBlackholeTail is a real cut, and the default is minimal.

Before
tailBehavior: "pi-default",

const sourceMessages = [
  ...event.preparation.messagesToSummarize,
  ...event.preparation.turnPrefixMessages,
];
const summary = compile({
  messages: convertToLlm(sourceMessages),
});
After
tailBehavior: "minimal",

const tail = resolveBlackholeTail({
  tailBehavior: config.tailBehavior,
  firstKeptEntryId: event.preparation.firstKeptEntryId,
  messagesToSummarize: event.preparation.messagesToSummarize,
  turnPrefixMessages: event.preparation.turnPrefixMessages,
  branchEntries: event.branchEntries,
});
const summary = compile({
  messages: convertToLlm(tail.sourceMessages),
});

New files: tail.ts and tail.test.ts. Pair with Cognee; they share the compact contract. progress.md cites ~20k recent tokens left in context before this cut.

Builtin /settings is a structured form (pi.settings). piv-provider-settings.ts adds a Providers submenu that lists catalogs and refetches one provider on demand. Pair with theme E.

E. Provider catalog

Before

Every normal piv launch refreshed models from the local OpenAI-compatible endpoint. Cached catalog could start in the background; cold launch waited.

After

Launch loads last valid models.json and injects the local API key. No /v1/models on startup. Refetch is an explicit settings action. refetchProviderCatalog is exported for that UI.

Separately, packages/ai/src/image-models.generated.ts is a generated 661-line rewrite. It does not belong in a subagent or Cognee commit. Drop it or regenerate in its own change.
